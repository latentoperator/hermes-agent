## Key Contract Verification

### Contract A: Taskless sessions with kanban toolset → routing tools only, no worker protocol

Confirmed. Three lifecycle mutations (`kanban_complete`, `kanban_block`, `kanban_heartbeat`) are now gated exclusively on `_check_kanban_worker_mode` which checks only `HERMES_KANBAN_TASK`. The `_kanban_worker_guidance` string is set to `""` when the env var is absent. Taskless orchestrators retain `{kanban_list, kanban_show, kanban_comment, kanban_create, kanban_link, kanban_unblock}`.

### Contract B: Dispatcher workers with HERMES_KANBAN_TASK → full worker protocol

Confirmed. All three lifecycle tools are available (worker mode passes), shared routing tools are available (kanban_mode passes), and the full KANBAN_GUIDANCE block is injected into the system prompt. Board-routing tools (`kanban_list`, `kanban_unblock`) remain hidden from workers via `_check_kanban_orchestrator_mode`.

## Prompt-Cache Analysis

No regression. The guidance gating is resolved once at `init_agent` time (session-static), same as before. The cache key is built from `stable_parts` in `build_system_prompt_parts`, which already includes the guidance block when present. Changing the gate from tool-presence to env-var does not alter the caching mechanism.

## Fail-Closed Behavior

- `HERMES_KANBAN_TASK` unset → empty guidance string, no lifecycle tools → no worker protocol. Correct.
- `HERMES_KANBAN_TASK` set to empty string → `os.environ.get()` returns `""`, falsy → no worker protocol. Acceptable fail-closed.
- `HERMES_KANBAN_TASK` set but agent_init bypassed → `system_prompt.py` fallback (line 233) injects `KANBAN_GUIDANCE`. Correct.
