**W1 — `supersedes_task_id` alternate key is undocumented**  
`tools/kanban_tools.py:892`: `_handle_create` accepts both `supersedes` and `supersedes_task_id` from args, but only `supersedes` appears in `KANBAN_CREATE_SCHEMA`. ## Suggestions

**S1 — Pre-existing prompt-size guard test needs updating (not from this diff)**  
`tests/tools/test_kanban_tools.py::test_kanban_guidance_prompt_size_bounded` fails on both the base commit and this branch: `KANBAN_GUIDANCE` is 6040 chars vs the 5500 ceiling. The test guard was set when the kanban-worker and kanban-orchestrator skills were separate files; folding them into the always-injected guidance grew the block past the ceiling without bumping the test threshold. This is unrelated to the supersedes change, but should be fixed separately (either trim the guidance or raise the ceiling).

## Looks Good

- **Correct lifecycle contract.** Originals close only when `supersedes` is explicitly passed — ordinary `parents`-only follow-ups do not close the parent (confirmed by `test_create_task_parent_without_supersedes_does_not_close_blocked_original`).
- **Validation.** Every superseded ID must also be a parent. Unknown IDs raise `ValueError`. Self-supersede blocked. Deduplication applied. (Confirmed by `test_create_task_supersedes_must_also_be_parent`.)
- **Idempotent.** Already-done/archived originals emit `superseded_noop` instead of double-closing.
- **Complete state cleanup.** On the superseded original: `status='done'`, `result` set, `claim_lock`/`claim_expires`/`worker_pid`/`block_kind`/`block_recurrences` all cleared.
- **Audit trail.** `superseded` event with `continuation_task_id`, `actor`, and `run_id`; run outcome set to `superseded` with metadata `{superseded_by, actor}`. Falls back to `_synthesize_ended_run` when no active run exists.
- **Transaction safety.** `_mark_tasks_superseded_by_continuation` and `recompute_ready` use their own `write_txn` inside `create_task`'s outer `write_txn` — SQLite converts nested `BEGIN IMMEDIATE` to savepoints, so status-read + update are atomic.
- **Three surfaces consistent.** CLI (`--supersedes` append arg), tool schema (`supersedes: array<string>`), dashboard (`supersedes: list[str]` in POST body). All three pass through to `kb.create_task(supersedes=...)`.
- **No race.** Concurrent supersede attempts are serialized by the write transaction; the second sees `status='done'` and emits `superseded_noop`.
- **`recompute_ready` called after supersede.** Ensures the continuation card is promoted from `todo` to `ready` when its parent is now done (confirmed by dashboard test asserting `continuation.status == "ready"`).
