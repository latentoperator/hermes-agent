## Root cause (confirmed)

The kill/pkill branch (Branch D) of `_GATEWAY_LIFECYCLE_PATTERN` used `p?kill\b` with no leading word boundary. Python word boundaries are zero-width assertions between a `\w` and a `\W` (or start/end). In `skill`, the `k` of `kill` is preceded by `s` — both `\w`, so no boundary exists *before* `kill`, but the trailing `\b` after `kill` still matched (the `l`→non-word transition). Combined with later `hermes` + `gateway` tokens on the same line, benign prose mentioning skills + Hermes + gateway satisfied the old pattern. Adding `\bp?kill\b` requires a word boundary *before* the optional `p`, so `skill`/`skills`/`SKILL.md` can no longer start the match.

## Change diff reviewed

```
 cron/lifecycle_guard.py | Branch D
-    r"|(?:p?kill\b[^\n]*\bhermes\b[^\n]*\bgateway)"
-    r"|(?:p?kill\b[^\n]*\bgateway\b[^\n]*\bhermes)"
+    r"|(?:\bp?kill\b[^\n]*\bhermes\b[^\n]*\bgateway)"
+    r"|(?:\bp?kill\b[^\n]*\bgateway\b[^\n]*\bhermes)"
```

Two-character conceptual change (one `\b` prefix per alternative). No other branches touched. Inline comment updated to explain the leading boundary. Correct and minimal.
